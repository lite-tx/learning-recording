# Learning & Recording 职责边界审查 v0.1

## 审查结论

目前 Learning 和 Recording 没有实质性的职责冲突。它们会处理同一段学习经历，但发生在不同时间，服务于不同目的：

- Learning 在学习正在发生时，帮助用户继续理解当前问题。
- Recording 在用户决定记录时，回顾已经发生的学习过程，整理出未来可以重新理解的笔记。

两者共享对话上下文，不需要额外建立固定的交接报告，也不需要把相同内容重复实现一遍。

## 两个 Skill 分别负责什么

| 范围 | Learning | Recording |
|---|---|---|
| 时间位置 | 学习进行中 | 学习之后，或用户需要整理资料时 |
| 主要目的 | 帮助用户把当前问题弄清楚 | 留下以后能够帮助重新理解的记录 |
| 主要动作 | 讨论、解释、推导、检查分歧、调整学习范围 | 回顾对话、选择关键经历、组织个人笔记 |
| 对分支的处理 | 管理当前分支，帮助用户适时回到主线 | 只保留对理解主线有影响的分支及其联系 |
| 输出 | 当前对话中的解释、推导、代码或结果 | 草稿、学习日记或用户指定的记录 |
| 是否自动触发记录 | 不负责 | 不自动；由用户主动调用或明确提出记录需求 |

## 看起来相似的部分，为什么不算冲突

### 对话中的理解变化

Learning 需要观察用户现在理解到哪里，以决定接下来怎么解释、是否补充中间步骤。

Recording 则在事后回顾这些变化，挑出未来重新理解时真正需要的部分。

同一段对话会被两者使用，但用途不同：一个用于继续学习，一个用于保存学习经历。

### 学习主线与知识分支

Learning 在分支发生时，帮助用户记住原来要解决什么，以及何时可以回到主线。

Recording 不需要重新管理学习路线。它只需在回顾时判断某个分支是否解释了主线中的关键障碍；如果有，就保留它与主线的联系。

### 用户当前理解与长期记忆

Learning 可以利用当前上下文和平台已有的记忆，了解用户已经知道什么。

Recording 需要如实写下本次对话中实际出现的想法和变化，但不负责建立一套长期的学习者模型，也不负责给用户的知识水平打分。

## ChatGPT、Memory 与 Notion 的边界

| 能力 | 应承担的工作 | 不应让 Skill 重复实现的内容 |
|---|---|---|
| ChatGPT 对话上下文 | 提供当前对话中已经发生的内容 | 不需要 Learning 生成固定交接摘要，才能让 Recording 使用同一对话 |
| ChatGPT Memory | 保存平台可用的长期偏好或概括性背景 | 不把每篇日记复制成 Memory，也不自行实现一套跨会话记忆系统 |
| 历史对话检索（若当前可用） | 在用户明确要求回顾过去时，查找实际可访问的历史内容 | 不假设模型可以任意读取完整聊天档案 |
| Notion | 保存长期笔记，提供真实日记样本和历史资料 | 不把 Notion 页面管理流程写成 Recording 的核心思想 |
| GitHub | 保存 Skill、设计文档和版本变更 | 不把每次学习记录自动写入 GitHub |

Memory 与 Notion 不是相互替代的：Memory 适合平台保留的用户偏好和概括性背景；Notion 保存用户明确整理的、可长期查阅的完整记录。Recording 负责根据用户要求整理内容，并在需要时调用 Notion 工具，不负责重新实现这两种存储机制。

## 联合使用时的实际情况

**同一对话：**

用户调用 Learning 学习某个问题。讨论过程中出现初始设想、卡点、推导和阶段性结论。用户随后主动调用 Recording。Recording 直接回顾当前对话，挑选有助于未来重新理解的内容并写成记录。Learning 不需要提前准备报告。

**跨对话：**

用户在新对话中调用 Recording，要求整理前几天的学习经历。Recording 只能使用当前上下文和实际可访问的历史资料。如果关键对话无法取得，应请用户提供原对话或相关内容，不得根据零散记忆补造过程。

**只需要直接解答：**

用户没有调用 Learning 或 Recording，只问一个普通问题时，正常回答即可。不必启动学习流程，也不必生成日记。

**只想保存一个结论：**

用户调用 Recording，但只要求保存一个结论或代码时，按指定范围整理。不要因为 Recording 的目标是保留学习过程，就把一个简单留档需求扩展成完整日记。

## 当前需要保持的边界

- 不增加 Learning 到 Recording 的固定交接报告。
- 不要求 Learning 在结束时自动总结或生成日记。
- 不让 Recording 重新讲授或重新解决已经结束的学习问题。
- 不让 Recording 维护长期学习者模型、记忆系统或自动评分。
- 不把 Notion 的页面操作和 GitHub 的版本管理写成核心记录思想。
- 两个 Skill 都由用户主动选择；需要一起使用时，用户可以在同一对话中先后调用。

## 审查结果

目前没有发现需要为了解决职责冲突而修改 Learning 核心指令的地方。Recording 中关于“同一对话直接回顾当前上下文、跨对话只使用实际可访问资料”的说明已经足够。

下一步应检查两个 Skill 是否能独立调用，以及插件配置能否按预期提供显式调用入口。职责边界审查本身不要求增加新的 Skill 规则。
