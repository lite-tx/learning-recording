# 案例回放

> 案例来自实际学习对话，经整理而成。用于检查设计能否解释已发生的问题，**不等于对插件的独立验证**。

## 案例 A — LeetCode 453：不完善的初始方案

**最初设想：** 反复找最大值，让其他 `n-1` 个元素加一，直到相等。

**对话中的变化：** 讨论动态维护与循环成本；观察相对差距；将 `n-1` 个元素加一等价看成一个元素减一；最后推得 `total - n * min`。

**需要检验的设计：** 能否允许正确但低效的初始设想存在，同时在合适的地方揭示优化方向，而不是预先覆盖思考过程？

## 案例 B — LeetCode 3841：从理论切回应用时的跳步

**已有理解：** DFS 子树编号与树状数组固定区间覆盖规则。

**具体矛盾：** `bit[3]` 负责 `[3,3]`，其差分值可以为 0；但 `ask(3)` 返回的累计变化是 `delta`。教学中曾跳过 `diff` 的引入，直接从树状数组讲到 `change`，造成断层。

**补足的关系：** 子树修改 → DFS 连续区间 → 差分边界 `diff` → 树状数组维护 `diff` 的区间异或 → `ask(i)` 查询 `diff` 前缀，恢复 `change[i]`。

**需要检验的设计：** 用户指认不一致时，AI 能否先检查自己遗漏了什么关系，而不重复讲已经理解的基础知识？

## 案例 C — C++ vector / reserve：局部记忆偏差

**已有理解：** `vector` 在重新分配内存时会让此前的元素指针与迭代器失效。

**具体偏差：** 曾以为 `reserve()` 不会触发重新分配；后发现混淆了 `size` 与 `capacity`。

**观察：** 具体例子能够修正这个偏差，但不能因此规定每个已解释的问题都必须追加小测验。

## 案例 D — C++ 伪共享：正在形成的硬件解释

**初步设想：** 两个原子变量分别由不同线程更新，软件上没有数据竞争，性能影响可能来自硬件缓存管理。

**解释方向：** 缓存行是缓存一致性操作的单位；两个核心反复更新同一行的不同变量，可能造成缓存行所有权来回争用。需区分这个机制与普通遍历顺序造成的局部性差异。

**观察：** 学习者指出「独立维护缓存行」的说法不清楚，AI 应把抽象术语换成明确的硬件动作，而不扩大到无关的缓存知识。
