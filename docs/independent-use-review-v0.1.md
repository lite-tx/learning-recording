# Learning & Recording 独立使用审查 v0.1

## 审查结论

从当前两个 Skill 的指令、目录和调用配置来看，Learning 与 Recording 都可以独立承担各自的任务。它们可以在同一对话中先后配合，但没有相互依赖。

这次是设计和配置层面的审查，不等于已经验证 ChatGPT 安装后的实际调用。真实的触发体验仍需在插件打包、安装后测试。

## 场景一：只使用 Learning

**场景：** 用户主动调用 Learning，想学习一个 C++ 概念或算法题。

**预期行为：**

- Learning 根据用户当前的理解和目标推进讨论。
- 可以解释、推导、示范或直接完成用户要求的工作。
- 不要求 Recording 参与，也不自动生成日记。

**审查结果：通过。**

Learning 的核心指令完整描述了学习协作方式，没有依赖 Recording 的内容。它的调用配置也设置为显式调用。

## 场景二：只使用 Recording

**场景：** 用户新开一个对话，想整理之前完成的学习经历，或者只保存一段代码、结论和资料。

**预期行为：**

- Recording 可以独立调用，不要求先调用 Learning。
- 如果本次学习过程就在当前对话中，直接使用当前对话。
- 如果用户要求整理过去的学习，但原对话不在当前上下文中，只使用实际可访问的历史资料；关键内容缺失时请用户提供原对话、代码或相关片段。
- 如果用户只想保存一个结论或代码，就按指定范围整理，不扩展成完整日记。

**审查结果：有条件通过。**

Recording 能独立工作，但记录的准确程度取决于是否有足够的原始材料。它不能凭空恢复无法访问的历史对话。

## 场景三：同一对话中先 Learning，再 Recording

**场景：** 用户先调用 Learning 完成学习，之后主动调用 Recording。

**预期行为：**

- Learning 正常完成当前学习任务，不需要预先生成交接报告。
- 用户主动调用 Recording 后，Recording 直接回顾当前对话。
- Recording 选择有助于未来重新理解的内容，整理成个人记录。

**审查结果：设计通过。**

两个 Skill 使用同一段对话，但用途不同。Learning 负责当下的理解推进，Recording 负责事后的内容整理。无需额外交接文件。

## 场景四：只保存一段代码或一个结论

**场景：** 用户不需要完整学习日记，只想保存一段代码、公式或结论。

**预期行为：**

- 按用户指定的范围整理。
- 不强行添加学习过程、感想、口诀或完整日记结构。
- 用户只要求草稿时，不擅自写入外部平台。
- 用户明确要求保存时，再使用相应工具并确认结果。

**审查结果：通过。**

Recording 的指令已明确支持局部留档，不会把所有记录需求都扩展成完整日记。

## 显式调用配置

两个 Skill 分别拥有自己的目录、SKILL.md 和 agents/openai.yaml：

- learning：allow_implicit_invocation: false
- recording：allow_implicit_invocation: false

这表示设计目标是让用户分别主动调用，而不是让其中一个 Skill 自动触发另一个。是否能在目标 ChatGPT 界面中按预期显示和切换，仍需安装后验证。

## 审查结果与后续工作

- 两个 Skill 可以独立使用，不要求同时启动。
- 同一对话中可以先后调用，不需要固定交接报告。
- Recording 可以处理完整日记，也可以处理局部资料留档。
- 跨对话记录依赖实际可访问的历史内容或用户提供的材料。
- 当前没有发现需要为独立使用而修改核心指令的地方。

下一步进入插件整合与打包检查。安装后再验证两个 Skill 是否能分别显式调用，以及 Notion 等外部工具是否能按预期协作。
