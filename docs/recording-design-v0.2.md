# Recording 设计 v0.2

## 想留下什么

一次学习之后，留下能帮助用户未来重新理解的记录。记录的价值在于保留用户怎样从最初的想法走到后来认识的过程，让未来的自己能够沿着这些线索重新建立理解。

## 保留思考的来路

从本次实际对话中选择对理解有影响的部分：用户最初怎么想，遇到了什么问题，哪些讨论推动了理解，最后形成了什么认识，事情进行到了哪里。它们是理解过程中的线索，不是每篇日记都必须填满的栏目。按思维之间的联系组织内容，不需要复述每条消息。

## 写成用户自己的笔记

记录应读起来像用户自己的笔记，而不是 AI 对用户的学习评估或知识讲义。参考真实日记和当前对话：当前对话用于确认本次事实，历史日记主要提供书面表达和段落习惯。保留用户自然、直接的表达，不刻意拔高，也不机械复制旧日记里的句子。

## 如实呈现理解变化

用户的猜测、AI 的解释和讨论后形成的结论，要按实际发生的过程呈现。用户说理解了，只能说明对话中具体讨论的部分得到理解。代码、运行和测试状态也要准确；没有依据的心理活动、感受和掌握程度不要补写。

## 按需要保存成果

正文以思考过程为主；代码、公式、图表和资料按需作为附属内容保留。记录形式根据本次内容选择，不强制套用算法日记的结构。用户要草稿就先给草稿，明确要求保存时再写入指定位置。

## 与 Skill 的边界

- 本文记录 Recording 的设计思想。
- `skills/recording/SKILL.md` 是供模型实际使用的精简指令。
- `skills/recording/references/examples.md` 用真实学习经历说明指令的实际含义。
- Notion 的具体页面操作、插件调用配置和 Git 版本管理属于工具或项目实现，不放进 Recording 的核心思想中。
